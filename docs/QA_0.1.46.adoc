The exact digest matches a 0.1.1 optimized black Tarot pack. Source verification found noncanonical attribute keys (`cardNumber`, `majorNumber`, `rankNumber`, `sourceFile`) in the 0.1.0 and 0.1.1 metadata. Those keys fail the canonical `tavi_assets.metadata._token` lowercase identifier constraint.

Studio's Python `review_cli.py` previously used `json.dumps(...,ensure_ascii=False)` as the final stdout response. In a redirected native Windows process, a legacy ANSI code page may encode a Unicode display title in non-UTF-8 bytes. Rust's `serde_json::from_slice` then fails even though Python constructed a valid response. The fix escapes non-ASCII at the JSON wire boundary, retaining Unicode when decoded by Rust. The canonical `invalid attribute key` reason is added to the *fixed* allowlist; arbitrary exceptions stay hidden. **Nothing is automatically approved.**
