== 0.1.43 implemented changes

* The selected submission now exposes an explicit blueprint-review selector and recheck action beside its findings. A recheck uses the same retained SHA-256 source, resets prior approval in the trusted boundary and does not import, install, price or publish.
* Canonical validation, required blueprint completeness, and local human approval are clearly distinct. An unselected blueprint is an actionable review requirement rather than an opaque all-purpose validator failure.
* For the generic `tarot-standard-78` profile, the UI states that it expects exact `tarot.major.*` and `tarot.minor.*` identifiers. The observed `tarot.card.*` IDs are NOT automatically remapped, and having 79 resources does not imply the right faces and card back. Actual producer mapping is a high-priority review item.
* Submission review now opens package inspection on demand rather than injecting two full scroll regions. Original package contents use native-controlled 12-entry pages and a compact adjacent preview that moves below the list at narrow sizes. Stale in-flight previews cannot overwrite a newer selection. Existing digest/path/media checks and read-only Tauri IPC remain authoritative.
* No canonical validator or blueprint schema change; no source package rewrite; no GitHub, LoopRD, Wallet or remote preview integration; no automatic publication.
