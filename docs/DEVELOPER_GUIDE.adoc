= Developing a TaviX application on a PC
:toc:

== Fast start

This guide targets the **0.1.9 TaviX source/tooling release**, with protocol standard `tavix/1.0`. Start with `../examples/hello-tavix` rather than an Atrium/Companion release; it is deliberately self-contained and needs no Tavi account, backend or host SDK.

From the repository root on a PC with Python 3.10+:

[source,powershell]
----
python tools/tavix_package.py validate examples/hello-tavix
python tools/tavix_package.py pack examples/hello-tavix hello-0.1.0.tavix
python tools/tavix_package.py validate-archive hello-0.1.0.tavix
python tools/local-client/server.py
----

Open `http://127.0.0.1:8765/tools/local-client/index.html`, choose `hello-0.1.0.tavix`, click *Install local .tavix*, select the installed entry and launch it. The local client is a browser-based loopback developer preview; it isn't Tavi for Windows. Don't upload unpublished secrets into it or assume its iframe is hardened against untrusted code. Delete the temporary output `.tavix` before creating a source ZIP for ZipRunner.

== SDK-capable applications

For embedded Tavi features, read `TAVIX_CONTRACT.adoc` and use a **locally bundled** SDK compatible with the selected Tavi host. Atrium 1.0.5 ships one example of such an SDK at `extensions/inc.thebigtree.tavi.atrium/1.0.5/ui/tavix-sdk.mjs`. The host's capabilities may change between Tavi versions; request `host.info`, inspect `features`/grants and handle errors. The preview client will not respond to host SDK calls; do not treat that as an app-package failure.

Do not hardcode authenticated identities, wallet authority, messaging privileges or LoopRD server endpoints into a `.tavix`. Production game authority, server APIs and multiplayer testing are outside this toolchain.

== Local validation and distribution

Use `tools/local-client/qa.py` for exact staged package evidence. Use `tools/repository.py stage` only after reviewed producer output exists; its immutable staging operation updates the local catalog but does not push. Publishing the repository is an operator action and triggers the GitHub Pages workflow for reviewed main-branch changes. See `TAVIX_PACKAGE_FORMAT.adoc` for the immutable archive and catalog contract.

== Integrating another component

Other components should retrieve the source contract and machine-readable index via the exact Git commit (see `INDEX.adoc`). Record the target Tavi host version, package/manifest version, verified SDK entrypoint and expected capabilities in their own project. When one of these changes, request a corresponding TaviX contract update in the same reviewed development pass; don't silently reinterpret an old integration contract.

== Classifying games (TaviX 0.1.10)

For a new game set `"kind":"app"` and optionally `"classification":{"type":"game","categories":["cards","solitaire"]}`. See `../examples/classified-game/manifest.json` and `TAVIX_CLASSIFICATION.adoc`. The standalone TaviX preview validates/displays this metadata, but Tavi 0.3.124 rejects the new key and does not expose the proposed trusted game-inventory API. Do not depend on `games.installed.list` or `games.installed.open` until the target host reports feature `tavix.installed-games/v1` and Tavi/Atrium have independently implemented the integration.

== Declaring shared assets (TaviX 0.1.11)

Read `TAVIX_ASSET_DEPENDENCIES.adoc` and `../examples/asset-consumer/manifest.json` for a complete game-classified extension that requests a specific Tavi Assets card pack and customization. Validate with `python tools/tavix_package.py validate examples/asset-consumer` and package normally. This fixture does not install packs or authorize purchases. Tavi 0.3.141 still rejects these new manifest fields and permissions; only a future reviewed host may approve and advertise `tavi.assets/v1`. The local TaviX preview cannot exercise the production asset SDK.

== Privileged asset registry administration requests (0.1.12)

The packable `examples/registry-admin-request/` fixture demonstrates requesting `assets.registry.admin/v1`. The local TaviX client can preview the panel but never provides registry admin authority. Before enabling Tavi Asset Studio staging, pricing, publishing or revocation, require explicit reviewed-package host approval, authenticated user and LoopRD `ecosystemAdmin` plus per-operation permissions. Inspect link:TAVIX_REGISTRY_ADMIN.adoc[the proposed host contract]; the transport is not implemented by TaviX.


== Native file picker reference (0.1.13)

To build the self-contained `.tavia` import test application, run `python tools/tavix_package.py pack examples/local-file-import /tmp/example.org.local-file-import-0.1.0.tavix` and `python tools/tavix_package.py validate-archive /tmp/example.org.local-file-import-0.1.0.tavix`. Run `node --test tests/test_local_file_sdk.mjs` for mock host tests. The app's `ui/tavix-sdk.mjs` is a copy of the new reference `sdk/tavix-sdk.mjs`; historical staged extension SDK files are not modified. The test app cannot open the native picker in Tavi 0.3.141 or the loopback preview: the host must first implement and advertise `tavix.local-file-import/v1` and grant `files.local.import`. Read link:TAVIX_LOCAL_FILE_IMPORT.adoc[the contract] before building Asset Studio.

== Shared icon and typography kit (0.1.14)

Read link:TAVIX_UI_KIT_001.adoc[the UI kit specification]. Run `python tools/tavix_package.py validate examples/ui-kit`, then pack and install `examples/ui-kit` in the local preview. The complete UI kit source lives at `sdk/ui-kit/`; an app must *bundle it locally* with its own assets. Use `createTaviIcon('search')`, keep accessible names on interactive controls, and import `ui.css` for the system-font stack. Do not fetch CDN icon fonts or implement your own Tavi Back bar. Existing games may use their own rendering. Native viewport acceptance still belongs to Tavi.

== Native-looking TaviX applications (0.1.15 developer-readiness pass)

Copy `sdk/ui-kit/` into the `.tavix` app's own UI directory; sandboxed iframes cannot read the Tavi host's stylesheet. Build an embedded layout first and use `createTaviUIController(root, {sdk})` from the portable `ui.js` for automatic theme, width and host-event synchronization. Always use `controller.dispose()` on view teardown. The helper neither creates SDK permissions nor duplicates Tavi navigation. See `docs/TAVIX_UI_KIT_001.adoc` for the contract and `examples/ui-kit/` for the installable example.

Static source/archive check: `python tools/tavix_ui_conformance.py --package examples/ui-kit` or `--package path/to/example.tavix`. This checks exact offline kit bytes and package integrity, but does not replace Windows/Android/device acceptance.


== Review the Store appearance before staging (0.1.18)

Package and install the private developer example under `examples/store-editor/` as described in link:TAVIX_STORE_EDITOR_001.adoc[the Store Editor guide]. It runs offline and supports desktop/phone/tablet Store catalog and product-detail previews. No Store or host contract is added by this example; Tavi's native file picker and download behavior require separate acceptance.
