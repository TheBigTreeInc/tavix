== Operator evidence

The operator-confirmed Studio v0.1.38 reported both TAVIX_VALIDATOR_READY and TAVIA_VALIDATOR_READY, but inspection of the same .tavia (digest prefix `f5bed8416763`) repeatedly generated `TAVIA_VALIDATOR_UNAVAILABLE`, `BLUEPRINT_TYPE_MISMATCH` and missing-card resources, then `STUDIO_VALIDATOR_PROTOCOL`. Readiness means the module can load; it does not certify validation of a particular package.

== Source change

* `review_cli.py`: map canonical `AssetImportError` outcomes to their specific codes. Preserve rejected-archive, timeout, failed-subprocess and invalid-protocol distinctions; do not invent a reason from the package digest.
* `review_cli.py`: suppress incidental stdout from trusted internal routines and always emit exactly one bounded JSON envelope, even for unexpected exceptions. Never forward raw traceback, usernames, paths, manifest strings or credentials.
* `studio_diagnostics.py`: allowlist new safe codes and clarify that readiness checks module load rather than an arbitrary .tavia acceptance.
* `src/main.tsx`: default .tavia inspections to no blueprint. Require explicit matching blueprint before review approval; a mismatch does not create 53 misleading missing-card findings.
* Preserve all existing `.tavix`, `.tavia`, game/catalog bytes, reviewer persistence, approvals and official-store publish restrictions.
