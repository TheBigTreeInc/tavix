= TaviX Studio 0.1.53 — publishing readiness and Connection UI repair
:toc:

== Scope and observed problem

Operator Windows screenshot from 0.1.52 displayed `GITHUB_NATIVE_ADAPTER_PENDING` in Connections even though an operator-only GitHub CLI release gateway exists in Publishing. The previous Connections layout showed oversized diagnostic cards and local review approval was visually conflated with release readiness. This pass changes source-owned Studio presentation/diagnostics only.

== Implemented

* Connections presents two compact rows for local TaviX and Tavi Assets validator readiness. Detailed gateway codes remain visible on request and in diagnostics, but publishing status lives in the Publishing workspace.
* Safe local health code `GITHUB_RELEASE_GATEWAY_AVAILABLE` means only that the gateway source is present. It NEVER means configured repository, signed-in `gh`, successful GitHub network read or permission to publish. `LOOPRD_NATIVE_ADAPTER_PENDING` remains pending.
* Publishing checks the pre-existing `gh auth` command independently from public release discovery; a missing `gh` installation cannot hide public read results. Explicit **Check GitHub sign-in**, HTTPS destination probe and **Refresh live GitHub releases** remain read-only.
* Publishing displays four independent facts: saved destination, observed `gh` sign-in, fetched live releases, and LoopRD official-store adapter status. Unsaved target edits invalidate cached remote status and disable draft/public release requests.
* A cached receipt is only displayed and actionable when matching both the selected exact artifact digest and the currently saved destination repository.
* Submission review calls out local approval and separately warns for `ASSET_DEPENDENCIES_EXTERNAL`; the approval is never asserted to be remote publication or verified installed-pack compatibility.
* No source checkout operations, Git push/pull, package writes, credentials, Gold/Wallet entitlements, Tavi Assets backend changes or automatic releases are introduced. Existing exact SHA-256, manual two-confirmation, approved-review and LoopRD gates stay in force.
